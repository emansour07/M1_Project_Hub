From Revit checks
to the dashboard.

Run the M1 checkset locally, review the findings, then publish a report linked to the exact ACC model version.

Start with one model. This 19-check pilot uses Autodesk’s published Revit 2024 check definitions. Its XML structure has been validated; the first run must confirm compatibility with your installed Revit and Model Checker versions. The dashboard receives results—it does not run Revit.

1. Install Model Checker

  1. If Revit already shows BIM Interoperability Tools → Model Checker, continue to step 2.
  2. Otherwise, close Revit and install Autodesk Interoperability Tools for Revit for your Revit release. Configurator alone is not the checking add-in.
  3. Reopen Revit and locate the Model Checker panel.

Autodesk Model Checker download and installation ↗. The local tool is free; this workflow does not use paid cloud checking.

2. Prepare the model

  1. Select one model in ACC and record its exact filename, ACC version number and ACC file link.
  2. Open a copy of that version in its compatible Revit release. For a workshared model, use a detached copy for the pilot. Do not upgrade or save over the source model, or synchronise the test copy back to production.
  3. Identify its scoped asset and discipline. Start with the main model only. If linked models are also assessed, keep their results separate and record each model’s own ACC version.
  4. Download M1_Model_Checker_v1.xml using the button above.

Version example: if ACC displays V5, enter 5 in the import’s ACC model version field. Do not enter the Revit year or the filename’s revision code.

3. Load and run the checks

  1. In Revit, open BIM Interoperability Tools → Model Checker → Setup.
  2. Choose Open / Browse and select the downloaded XML.
  3. Confirm the name is M1 Model Health — Local Pilot v1. Review the 19 checks, then choose Save and Close.
  4. Select Model Checker → Run → Run Report.
  5. Review results and affected element lists. Family-size and duplicate checks may take longer on large models.

Button names can vary by release. See Autodesk’s illustrated Setup → Run → Export walkthrough ↗.

4. Export and review

  1. In the results window, select Export to Excel. Save the original report locally as evidence.
  2. Review findings before importing. Observations and counts do not automatically establish compliance.
  3. If a check fails to execute, is unsupported or was skipped, record Not checked, not Pass.
ResultWhen to use it
PassAn evaluated rule was satisfied.
FailAn evaluated rule found a non-compliance. Include the finding and element IDs.
Count / listAn observation such as warning count, file size, worksets or coordinates. No approved threshold is applied.
Not checkedThe check did not run, is unsupported or was skipped. Explain why.

5. Prepare the import table

The importer accepts CSV or XLSX, with one row per check per model. A native Autodesk export with nested headings or summary blocks may need to be flattened first. Do not upload the checkset XML as a QA/QC result.

  1. In M1, open Coordination & quality → Import & manage reports and sign in with your owner code. Team viewers can read published results without signing in.
  2. Under Register, select Local model QA/QC results.
  3. Click Download blank CSV template. Fill it in Excel and save as CSV UTF-8 or XLSX. Keep the original Revit export unchanged.

Use a distinct register per model. If importing multiple models together, give each row its own filename, version, asset and discipline.

6. Preview and publish

  1. Set a stable, unique Register name for this model, such as its full filename followed by “— Model health”. Do not add a date or version to the register name.
  2. Set Report date to the check date and select the prepared CSV/XLSX.
  3. Confirm Worksheet, Header row and Dates format. Map each field to its source column; leave unused fields unmapped.
  4. Select Default asset and Default discipline only when absent from the report. A default asset does not correct an invalid code already in a row.
  5. Click Preview scoped records. Review the rows and exclusions. Unknown or out-of-scope assets are excluded.
  6. Tick I reviewed the preview and any excluded rows, then click Publish report.
  7. Return to Coordination & quality → Model QA/QC and click Refresh. Filter by asset, discipline, result or date range. Use Export filtered CSV for a dated report.

7. Update the next version

After a new model version is uploaded, run the checks again. Import using the same register name and stable check IDs, with the new ACC version and report date.

Publishing replaces that register’s current rows. Include the complete latest report, not just changed findings. Rows absent from it are recorded as “not in latest report”; they are not automatically resolved.

The dashboard compares results with its latest folder scan. Matches scanned ACC version confirms a version match only, not that every check passed. A changed version requires another Revit run; Refresh alone does not run the checks.

8. Troubleshooting & coverage

Model Checker is missing

Confirm Interoperability Tools is installed for the same Revit release and restart Revit. Configurator alone is insufficient. Ask IT to install the matching add-in if installation is restricted.

The XML or a check fails

Record the Revit version, Model Checker version and exact error. Mark unsupported checks Not checked. Review using the matching Configurator before wider use.

The Excel report will not import

Select the correct worksheet and header. For nested summaries, use the blank template. Required fields are ID, title, result, model filename, ACC version and a valid asset or default asset. Use YYYY-MM-DD dates or choose the matching date order.

Excluded rows or duplicate IDs

Use confirmed scope codes; A51 is excluded. Each model/version/check ID combination must be unique. Combine element IDs and findings in one check row instead of repeating the check per element.

Model not found or version mismatch

Check the exact filename, numeric ACC version and asset, then refresh the folder data. If multiple files share a name, review their locations. A link alone does not resolve an ambiguous filename/version match.

Coverage

Warnings, file size, families, groups, in-place families, Revit version, design options, phases, worksets, project information, coordinates, links, levels, grids, imported CAD and selected duplicate family-instance conditions. The duplicate test is not an exhaustive geometry audit.

Use the dashboard’s existing Checker for filenames, original parcel codes, asset codes and required formats. Civil 3D and engineering design correctness require separate checks.

Asset information and COBie: requirements and parameter mapping remain pending client clarification. They are not scored by this pilot.
